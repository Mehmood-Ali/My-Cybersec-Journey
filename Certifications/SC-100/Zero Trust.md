### Zero Trust 

This module explains Zero Trust, a security strategy based on the principle of "never trust, always verify," as a defense against cyberattacks and threats, ensuring users authenticate and validate before accessing resources. 

 

Zero Trust is a comprehensive security strategy that monitors and controls six key pillars: identity, endpoints, applications, network, infrastructure, and data. It addresses security concerns in the evolving digital landscape, requiring strict identity verification, applying least privilege access, and assuming breach. The "trust no one and verify everything" rule ensures that every request, device, or user is treated as a potential threat. 

Traditional Network Security Approaches and Zero Trust Approach 

 

# Traditional Perimeter-Based Approach 

• Emphasizes on protecting network access with on-premises firewalls and VPNs. 

• Firewalls filter incoming and outgoing network traffic, preventing unwanted traffic and malicious software. 

• VPNs secure connections from one network to another, ensuring location stays private, data is encrypted, and identity is maintained as anonymous. 

• Traditional approach divides users into "trusted" and "untrusted" categories, limiting access to data, applications, and information. 

• Risks include malicious internal actors leaking sensitive information, cybercriminals gaining access using compromised credentials, users exploited as vulnerable entry points, and virus-infected devices connecting to the network. 

 

# Zero Trust Approach 

• Based on verifying users and devices, not just determining their location. 

• Provides quick responsiveness and protection required for a rapidly evolving digital landscape. 

• Users are verified at the perimeter and when moving from one part of the network to another. 

• Benefits include enhanced user experience, protection of IT assets, and monitoring security posture. 

• Adoption of the Zero Trust approach ensures the integrity, authenticity, and confidentiality of data, assets, and resources. 

 

## Zero Trust Approach to Cybersecurity 

 

# Key Components of Zero Trust Approach 

• Identity: Defined as users, services, and credentials used by applications and IoT devices. Controls and administers access to critical data and resources. 

• Endpoints: Any device connecting to the network, including cloud, on-premises, and remotely. Security policies are enforced uniformly across all endpoints. 

• Applications: Productivity tools through which users access their data. Controlled in-app permissions and monitoring for abnormal behavior are essential. 

• Networks: Means to access data. Use of network access controls and real-time monitoring can provide insights into threats. Network segmentation, threat detection and prevention tools, and encrypting network traffic can reduce attack likelihood and mitigate fallout from a breach. 

• Infrastructure: Covers all aspects of the digital domain, from on-premises servers to cloud-based virtual machines. Manages configuration and keeps software updated. 

• Data: Understands data, applies correct level of access control, implements strong data usage policies, and uses real-time monitoring to restrict or block sharing of sensitive data and files. 

 

## Zero Trust Approach to Identities 

 

# Identities in Zero Trust 

• Identities can be users, devices, or applications. 

• A successful Zero Trust approach involves securing these identities. 

• Identities are crucial for controlling access to sensitive data. 

 

# Authentication and Authorization 

• Zero Trust strategy involves continually verifying users' identities and other properties. 

• It relies on automated technologies and policy enforcement for security and user experience. 

 

# Authentication Methods 

• Passwords: Basic form of authentication based on known information. 

• Multifactor authentication (MFA): Requires more than one distinct factor to prove identity. 

• Biometric: Uses biological characteristics to verify identity. 

• Passwordless: Combines biometric, multifactor authentication, and mobile apps. 

 

# Strong and Weak Authentication 

• Strong authentication combines two or more factors to verify identity. 

• Weak authentication is flawed and uncertain, leading to easy password cracking or bypassing authentication. 

 

# Identity and Access Management Overview 

 

• Identity and access management is a crucial security layer that protects critical data, applications, software, devices, locations, and data transmission. 

• It involves working with password management tools, employee database systems, and on-premise and cloud applications. 

• Compliance with identity and access management and effective security policies can prevent hacking or other security breaches. 

• Methods of identification used include identification cards, personal identification numbers, smart cards, and biometrics. 

• Single sign-on (SSO) eliminates the risk of users holding copies of their credentials in various apps. 

• Multifactor authentication (MFA) requires more than one form of security and validation procedure. 

• Conditional or role-based access governs the level of access provided to a user or device. 

• Privileged access management (PAM) addresses user accounts with elevated permissions, oversees and monitors access privileges to sensitive data and resources, and governs which groups of users can access resources within the organization.

## Endpoint Protection and Security

# Zero Trust Principles
• Implement a "never trust, always verify" approach across all endpoints.
• Implement cloud-enforced security policies covering endpoint security, app protection, device compliance, device configuration, and risk posture.
• Securely provision, configure, and keep up-to-date the operating system and apps running on devices.
• Respond automatically and rapidly to security incidents and prevent extraction of organizational data from endpoints.
• Establish an access control system that only allows access to data through policy controls.

# Registering Endpoints with Cloud Identity Providers
• Register all devices with identity providers.
• Require modern authentication to manage identity information across the organization.
• Use passwordless authentication tools to increase security by requiring physical evidence for access.

# Grant Access Only to Cloud-Managed and Compliant Endpoints
• Grant access only to endpoints that meet security requirements.
• Define requirements using compliance policies and set remediation rules.

# Use Endpoint Threat Detection
• Implement threat detection for all endpoints to monitor risk and control access.
• Use threat detection to prioritize alerts, gain visibility into breaches, and take response actions to remediate threats.
• Feed information such as device risk into endpoint compliance policies and access policies.

• Least privilege access can be exercised by administrative accounts, emergency accounts, service accounts, and business user accounts. 

• An effective least privilege access management solution ensures correct level of access, secure endpoints, and effective compliance. 

## Cloud Impact on Applications and Shadow IT

# Cloud Services and Applications
• Cloud services are computing services delivered and accessed over the internet.
• Benefits of cloud applications include access from anywhere, rapid updates, different versions of the same app, and protection of app code.
• However, the increasing reliance on cloud applications can introduce security risks.

# Shadow IT
• The rise of cloud applications has led to an increase in the number and types of apps available.
• Unauthorized apps can introduce security risks into the organization, such as accessing critical data, changing or removing data, locking data in exchange for ransom, or gaining control of devices or networks.

# Zero Trust Approach to Cloud Applications
• Organizations need to balance access to apps with ensuring control to protect themselves and their users from risks.
• A Zero Trust framework can help organizations control and discover shadow IT, ensure appropriate permissions for app use, limit access based on real-time analytics, monitor abnormal behavior in apps, control user actions, and validate secure configuration options.

#Continuous Protection Process
• The process consists of three broad phases: discovering shadow IT, evaluating and analyzing compliance, managing and continuously monitoring, and implementing a continuous protection process.
• Cloud app discovery tools can help organizations discover and identify shadow IT, evaluate compliance, analyze usage, manage apps, and monitor apps.

#Protecting Sensitive Information and Activities
• Organizations should monitor and control how users behave inside cloud applications.
• Policies can include access policies, activity policies, and file policies.
• Real-time monitoring and control over access to cloud apps can be enabled.

#Strengthening Protection against Cyberthreats and Rogue Apps
• Advanced cloud app security capabilities include user and entity behavioral analytics (UEBA), anomaly detection, malware protection, and automated investigation and remediation.
