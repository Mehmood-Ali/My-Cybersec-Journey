# CISSP Domain 3: Cryptography (Deep-Dive Exam Notes)

## Why Cryptography Matters

Cryptography is one of the most important domains in cybersecurity because it enables nearly every major security service we rely on today.

Examples:

- HTTPS websites
- VPNs
- BitLocker
- Microsoft Entra ID authentication
- Digital signatures
- Software update verification
- Digital certificates
- DRM
- Cryptocurrencies
- Secure email

A useful CISSP mindset:

> Cryptography is not about hiding data.
>
> Cryptography is about providing security services.

---

# The 5 Cryptographic Services

Everything in cryptography ultimately supports one or more of these services.

## 1. Confidentiality

Confidentiality ensures only authorized individuals can access information.

Purpose:

- Prevent unauthorized disclosure
- Keep information secret

### Examples

- BitLocker
- HTTPS
- VPNs
- Encrypted emails

### CISSP Mapping

```text
Confidentiality = Encryption
```

---

## 2. Integrity

Integrity ensures information has not been modified.

Purpose:

- Detect unauthorized changes
- Verify consistency

### Examples

- File verification
- Software update validation
- Data integrity checking

### CISSP Mapping

```text
Integrity = Hashing
Hashing = Integrity
```

This is one of the most important associations in cryptography.

---

## 3. Authenticity

Authenticity answers:

> "Who did this come from?"

Examples:

- Verifying software came from Microsoft
- Verifying email sender identity
- Verifying a website is legitimate

---

## 4. Non-Repudiation

Non-repudiation prevents someone from denying an action.

### Non-Repudiation of Origin

Sender cannot deny sending a message.

### Non-Repudiation of Delivery

Receiver cannot deny receiving a message.

### Example

A digitally signed contract.

The signer cannot later claim:

> "That wasn't me."

---

## 5. Access Control

Encryption also enables access control.

If you control:

- Access to ciphertext
- Access to keys

You control access to data.

---

# Cryptographic Terminology

---

## Plaintext

Readable, unencrypted data.

Example:

```text
Password123
```

---

## Ciphertext

Encrypted, unreadable data.

Example:

```text
9A2F7D1A88EF...
```

---

## Encryption

Transforms:

```text
Plaintext
↓
Ciphertext
```

Uses:

- Algorithm
- Key

---

## Decryption

Transforms:

```text
Ciphertext
↓
Plaintext
```

Uses:

- Algorithm
- Correct Key

---

## Key (Crypto Variable)

A key is a secret string of bits used by an algorithm.

Think of the algorithm as:

```text
The lock
```

The key is:

```text
The actual key
```

The algorithm is usually public.

The key remains secret.

---

## Key Clustering

Occurs when:

```text
Different Keys
↓
Same Plaintext
↓
Same Ciphertext
```

Bad because:

- Reduces security
- Makes brute force easier

Good algorithms try to avoid key clustering.

---

## Work Factor

Work factor estimates:

> How difficult it is to break a cryptosystem.

Higher work factor:

```text
More Effort
=
More Security
```

---

# Initialization Vector (IV) / Nonce

One of the most tested cryptography topics.

## Definition

A random value used during encryption.

Purpose:

```text
Prevent Patterns
```

---

## Why Important?

Suppose:

- Same plaintext
- Same key

Without IV:

```text
Same Ciphertext
```

Attackers can identify patterns.

---

### With IV

Same plaintext

Same key

Different IV

↓

Different ciphertext

Much more secure.

---

## Memory Trick

```text
Nonce
=
Number Used Once
```

---

# Confusion, Diffusion & Avalanche

These measure algorithm quality.

---

# Confusion

Hides the relationship between:

```text
Key
and
Ciphertext
```

Changing one key bit should cause widespread ciphertext changes.

---

## Memory Trick

```text
Confusion
=
Key Focused
```

---

# Diffusion

Hides relationship between:

```text
Plaintext
and
Ciphertext
```

Changing one plaintext bit should dramatically alter ciphertext.

---

## Memory Trick

```text
Diffusion
=
Plaintext Focused
```

---

# Avalanche Effect

Measures both confusion and diffusion.

Ideal result:

A one-bit change causes approximately:

```text
50% Change
```

in ciphertext.

---

# Secret Writing Techniques

Before modern encryption, people focused on hiding messages.

---

# Steganography

Hides secret data inside non-secret data.

Example:

- JPEG
- PNG
- Audio files
- Videos

---

## Example

A secret message hidden inside a family photo.

The message exists.

Nobody knows it's there.

---

## Exam Tip

```text
Steganography
=
Hide Existence
```

---

# Null Cipher

Message hidden in plain sight.

Example:

First letter of every sentence forms hidden message.

---

# One-Way Cryptography

One-way means:

```text
Can Go Forward
Cannot Go Back
```

Used for:

```text
Integrity
```

---

# Hashing

Hashing converts:

```text
Variable Length Input
↓
Fixed Length Digest
```

---

## Requirements

Deterministic:

Same input = Same output

Always.

---

## Example

File A:

```text
Hash = ABC123
```

Change one bit.

New hash:

```text
Hash = XZY999
```

Completely different.

---

## Why?

Integrity checking.

# Two-Way Encryption

Encryption that can be reversed.

Requires a key.

Two major categories:

1. Symmetric
2. Asymmetric

---

# Symmetric Cryptography

Uses:

```text
ONE KEY
```

Encrypt:

Same key

Decrypt:

Same key

---

# Advantages

- Fast
- Efficient
- Strong
- Great for bulk encryption

---

# Disadvantages

## Key Distribution Problem

How do you securely share key?

---

## Scalability Problem

Keys grow exponentially.

Formula:

```text
N(N−1)/2
```

---

## Example

1000 users

Need:

```text
499,500 Keys
```

Not practical.

---

# Symmetric Algorithm Types

## Block Ciphers

Encrypt data in blocks.

Examples:

- DES
- 3DES
- AES
- Blowfish
- Twofish
- RC5
- RC6

---

## Stream Ciphers

Encrypt one bit at a time.

Example:

```text
RC4
```

---

# DES

Data Encryption Standard.

Specifications:

```text
56-bit Key
64-bit Block Size
```

---

## Exam Rule

DES is obsolete.

56-bit keys are too small.

---

# Triple DES (3DES)

DES performed three times.

Key Length:

```text
168 bits
```

Effective Security:

```text
112 bits
```

Because of:

```text
Meet-In-The-Middle Attack
```

---

# AES (Advanced Encryption Standard)

Originally:

```text
Rijndael
```

---

## Key Sizes

```text
128-bit
192-bit
256-bit
```

---

## Block Size

```text
128 bits
```

---

## CISSP Exam Rule

If asked:

> Best modern symmetric algorithm?

Answer:

```text
AES
```

# Asymmetric Cryptography

# Substitution Ciphers

Replace characters.

---

## Example

```text
CAT
↓
DOG
```

Characters replaced.

---

# Caesar Cipher

Earliest substitution cipher.

Each character shifted:

```text
+3
```

through alphabet.

---

# Monoalphabetic Cipher

One substitution alphabet.

Problem:

Patterns remain visible.

---

# Polyalphabetic Cipher

Multiple alphabets.

Reduces patterns.

More secure.

---

# Running Key Cipher

Uses long text source as keystream.

Often:

- Books
- Documents

---

# One-Time Pad

One of the most important CISSP concepts.

Requirements:

1. Truly random key
2. Key length ≥ message length
3. Key used once only

If these conditions are met:

```text
Unbreakable Encryption
```

---

# Transposition Ciphers

Instead of replacing characters:

Rearranges characters.

---

# Spartan Scytale

Ancient transposition cipher.

Uses matching rod diameter for encryption/decryption.

---

# Rail Fence Cipher

Letters written in zigzag pattern.

Read row by row.

Creates ciphertext.

# CISSP Exam Strategy

When you see a cryptography question, identify the security objective first:

```text
Need Confidentiality?
→ Encryption

Need Integrity?
→ Hashing

Need Authenticity?
→ Digital Signature / Certificate

Need Non-Repudiation?
→ Digital Signature

Need Fast Encryption?
→ AES

Need Secure Key Exchange?
→ Diffie-Hellman

Need Efficient Public-Key Crypto?
→ ECC

Need Verify Website Ownership?
→ Digital Certificate
```

The cryptographic algorithm is usually the second question.

The first CISSP question is always:

> "What security service are we trying to achieve?"
